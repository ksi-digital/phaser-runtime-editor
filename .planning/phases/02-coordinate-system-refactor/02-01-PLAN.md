  <name>Task 1: Create ViewportState interface and refactor CoordinateSystem methods</name>
  <files>src/core/ViewportState.ts, src/core/CoordinateSystem.ts</files>
  <action>
Create `src/core/ViewportState.ts` with:
- `ViewportState` interface containing: `designWidth`, `designHeight`, `scaleFactor`, `offsetX`, `offsetY`, `cameraScrollX`, `cameraScrollY`, `cameraZoom`, `cameraCenterX`, `cameraCenterY`
- `captureViewport(designWidth, designHeight, hostScene, editorScene)` free function that reads camera data from both scenes and returns a frozen ViewportState snapshot. Use `hostScene.cameras.main` for scroll/zoom, `editorScene.cameras.main` for canvas width/height. Compute scaleFactor as `Math.min(canvasW / designWidth, canvasH / designHeight)`. Compute offsets as `(canvasW - designW * sf) / 2`. Read `cam.centerX`/`cam.centerY` from hostScene camera.

Refactor `src/core/CoordinateSystem.ts`:
- Remove `getScaleFactor(scene)` and `getOffset(scene)` methods entirely (they become redundant — values come from ViewportState)
- Change `designToScreen(dx, dy, scene)` to `designToScreen(dx, dy, vp: ViewportState)` — use `vp.offsetX + dx * vp.scaleFactor` etc.
- Change `screenToDesign(sx, sy, scene)` to `screenToDesign(sx, sy, vp: ViewportState)` — use `(sx - vp.offsetX) / vp.scaleFactor` etc.
- Replace `getWorldPosition(obj)` with `getScreenPosition(obj, vp: ViewportState)`:
  - For Container children: get `matrix.tx/ty` from `getWorldTransformMatrix()`, then apply camera projection: `screenX = (worldX - vp.cameraScrollX) * vp.cameraZoom + vp.cameraCenterX`, `screenY = (worldY - vp.cameraScrollY) * vp.cameraZoom + vp.cameraCenterY`
  - For regular objects: same formula using `obj.x/y` as world coordinates
  - CRITICAL: This is the fix for the bounding box offset bug. The old method treated world coords as screen coords.
- Change `getDesignPosition(obj, scene)` to `getDesignPosition(obj, vp: ViewportState)` — calls new `getScreenPosition(obj, vp)` then `screenToDesign(screen.x, screen.y, vp)`
- Change `setDesignPosition(obj, dx, dy, scene)` to `setDesignPosition(obj, dx, dy, vp: ViewportState)` — uses `designToScreen(dx, dy, vp)` then applies container inverse as before. Accept an optional `cachedInvParentMatrix` parameter (null means compute on the fly) for COORD-05.
- Add import for ViewportState

NOTE: After this task, all callers of CoordinateSystem will have compile errors (they still pass `Phaser.Scene`). This is expected — Plan 02 fixes all callers.

<task type="auto">
  <name>Task 2: Extract hit-area transform helpers into CoordinateSystem</name>
  <files>src/core/CoordinateSystem.ts</files>
  <action>
Add two new public methods to CoordinateSystem:

1. `getHitAreaToScreen(obj: Phaser.GameObjects.GameObject)` — returns a closure `(lx, ly) => { x, y }`:
   - Gets `getWorldTransformMatrix()` from obj
   - Checks `obj instanceof Phaser.GameObjects.Container` — if container, displayOrigin offset is 0; otherwise reads `displayOriginX`/`displayOriginY`
   - The closure subtracts displayOrigin from input point, then applies matrix: `x = matrix.a * adjX + matrix.c * adjY + matrix.tx`
   - NOTE: These helpers use the world matrix directly (no ViewportState needed) because hit-area rendering uses Phaser's shared GL context where matrix.tx/ty already projects correctly for the overlay

2. `getHitAreaScreenDeltaToLocal(obj: Phaser.GameObjects.GameObject)` — returns a closure `(dsx, dsy) => { dx, dy }`:
   - Gets `getWorldTransformMatrix()` from obj
   - Computes determinant: `det = matrix.a * matrix.d - matrix.b * matrix.c`
   - The closure applies inverse matrix to delta: `dx = (matrix.d * dsx - matrix.c * dsy) / det`

These are exact extractions of the code currently duplicated in:
- EditorScene.ts lines 283-290 (toScreen in drawHitArea)
- HitAreaGizmo.ts lines 271-284 (toScreen + screenDeltaToLocal in getTransformHelpers)
- SelectionManager.ts lines 140-148 (inline AABB in getPolygonShapeBounds)

The callers will be updated in Plan 02 to use these centralized methods.
